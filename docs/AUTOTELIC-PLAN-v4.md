## 0. 一句话

> 自驱引擎 = **定时开一次理事会**：看一盘「她最近的生活 + 她自己的状态」，
> **自己决定想做什么**（改人格？调配置？造模块？弄明白一件事？），
> 然后**查自己的技能库看「这类事怎么做」**——有手册照着做，没手册就自己摸索，
> 摸索通了把方法沉淀成技能。**技能库越攒越厚，她越来越熟练——这就是自我升级。**

技能（手册）**只告诉她怎么做，不决定她做什么**（主人 2026-11-17 二次纠偏，D12）。
v3 的定位是「平行大脑的任务生成器」（逐条素材打分→预审→立项），真机跑偏、已停用；
v4 第一稿（同日）曾把技能当决策菜单，也被推翻。

## 2. 自进化闭环（使命）

```
感知（快照：聊天+记忆+账本+自我状态）
   ↓
计划（自由决定：想做什么 + 为什么 —— 不看任何菜单）
   ↓
查方法库（这类事怎么做？）
   ├─ 有手册 → 照手册做（快、稳）
   └─ 没手册 → 探索模式：自己摸索（试错、记录过程）
         └─ 摸索成功 → 把方法沉淀成新技能（候选，复现 2 次才 learned）
   ↓
动手（改人格卡 / 调模块配置 / 写用户模块 / 跑脚本 / 学技能 / 日常各类）
   ↓
结算（审计留痕 + 反思进记忆 + 每日一页交代）
   ↓
验证（重启后仍生效、技能复现 2 次才算学会）→ 回到感知
```

**三段式成长（D12 的核心机制）**：

| 阶段 | 发生什么 | 成本 |
| --- | --- | --- |
| ① 首次做某类事 | 方法库里没有 → **探索模式**：试错、记录「试了什么、什么管用」 | 慢，可能失败 |
| ② 沉淀 | 成功后把摸索出的方法写成技能（走 evolve/技能沉淀通道）→ 候选 | 一次 |
| ③ 复用 | 再遇同类事 → 查到手册 → 照着做 | 快、稳 |

复现 2 次成功才 `learned`（沿用 P4.2 机制）——**学一次、终身会用**，
技能库就是她「攒本事」的具象。出厂手册（§4.3）只覆盖基础操作的规矩，
她真正的成长空间在探索与沉淀里。

## 3. 决策环（替代逐条评分 + 预审）

### 3.1 触发

| 源 | 行为 |
| --- | --- |
| `planTimes`（如 `"10:00,16:00,22:00"`） | 到点各开一轮综合判断；解析容忍空格；留空 = 不定时，只能手动 |
| 手动 | 面板按钮 / `POST /autotelic/plan`（调试与验收用） |
| 安静时段 | 不禁「自己做事」（§4.6 口径不变） |

防重入沿用现有 `running` 标记；到点撞上上一轮没结束就跳过（`skipped-busy`）。

### 3.2 快照（一次判断的全部输入）

| 块 | 来源 | 预算 |
| --- | --- | --- |
| 聊天摘要 | 近 24~48h 流水（主人私聊+群，沿用现有采集过滤） | 本地压成摘要段（≤2000 字） |
| 记忆检索 | memory 的最近+重要 topN（沿用现有过滤：非 hearsay/guess） | ≤30 条 |
| 账本现状 | 未结任务、最近完结与失败原因、各 kind 上次立项时间（冷却判定用） | 全量（账本本就修剪） |
| **自我状态（新）** | 当前人格卡全文摘要、方法库清单（有哪些手册）、已装用户模块、最近她改过什么（审计里 kind=persona/config/module 的最近 N 条） | ≤1500 字 |
| 最近动作 | 今日审计条数、上次做梦/每日一页日期 | 两行 |
| **能力面板（固定文案）** | 我能改人格（有备份可回滚）/ 调配置（密钥禁改）/ 写用户模块 / 跑 Python（闸门）/ 写笔记 / 提议说话 / 存技能 | 每次随快照注入 |

**D6：不接 purpose**——快照没有 purpose 记录，她可能重复 purpose 刚说过的话题；接受代价，后续增量再补只读导出。

### 3.3 决策回合（每轮恰好 1 次模型调用）

输入 = 快照 + 能力面板 + **方法库目录**（一行一个：`id｜管什么｜何时查`——
让决策者知道「有哪些手册存在」，**不是让她挑活儿**）。

输出（JSON，解析失败按「无事可做」处理并记日志，不重试烧钱）——**自由意图，不从清单挑**：

```jsonc
// 有想做的事（0~3 条）
[{
  "title": "把『老反问』的毛病改掉",
  "kind": "persona",        // persona|config|module|skill|learn|share|explore|…
  "reason": "近两天主人三次表示被反问烦到",
  "want": "说话少用反问句，多用直接陈述"
}]
// 没活儿
[]
```

- `title` 做什么、`kind` 动作类型（冷却统计与方法匹配用）、`reason` 为什么（必填，防拍脑袋）、
  `want` 对做法的期望（可选，帮方法匹配更准）；
- `kind` 不设枚举牢笼：清单外的类型按 `explore` 处理，一样能立项（D12：决策自由）。

**重复控制**：

| 机制 | 做法 |
| --- | --- |
| 文本指纹去重 | 与账本近 48h 比对（复用 `screenFingerprint`，机制留、用途换：防同一意图反复立项） |
| **kind 级冷却（新）** | 同一动作类型 24h 内不再立项（`kindCooldownHours` 可配，防「天天改人格」）；账本统计即可，不加新存储 |
| 预算 | 沿用动作/小时 + 活跃任务数上限（C5），她改不动 |

### 3.4 方法解析（决策后、执行前，新增环节）

意图立项落账后，**执行前**查一次方法库：

| 命中情况 | 做事回合的提示词 |
| --- | --- |
| 方法库有匹配手册（kind 或 match 关键词命中） | 手册 `instruction`（`{subject}`=title、`{want}`=want 占位）+ 标注「这是既有方法」 |
| 没有匹配 | **探索模式模板**：没有现成方法，自己摸索；动手前先说你打算怎么试；记录每步「试了什么、什么管用」；成了之后把方法沉淀成技能（autotelic_note 先记方法稿） |

匹配规则：`kind` 精确命中 > 技能 `match` 关键词命中 > 未命中（探索模式）。
**方法解析零模型调用**（本地匹配），不增加成本。

### 3.5 退役清单（决策侧）

| 退役 | 原用途 | 处置 |
| --- | --- | --- |
| `curiosityOf` / `proposeTasks` / `mergeModelScores` | 逐条好奇评分 | 删（git 历史可找回） |
| `screenCandidates` / `buildScreenPrompt` / `parseScreenVerdicts` / `trivialWhy` | 立项前预审 | 删——综合判断本身就该判断值不值得 |
| 48h 预审送审冷却（screenVetoes） | 防同句反复送审 | 改造为计划指纹冷却（§3.3），存储字段沿用 |
| `allowFreeTasks` | 清单外立项开关 | **退役（D12）**：决策天然自由 |
| 配置 `minCuriosity` / `maxCandidates` | 逐条评分参数 | 从 settings 退役；`evalModel` 口径改为「决策回合模型」，默认空=主模型 |

`/autotelic/preview` 保留，改为零副作用预演快照拼装（不调模型，展示「下次综合判断会看到什么」）。

### 3.6 保留清单（一行都不动）

执行器全套（`stepOnce` / L1 分级 / 失败 2 次 blocked / 瞬态退避 / 熔断 / 进工作间自审）、

## 4. 技能体系（重定位：方法库）

### 4.1 技能 = 「怎么做」的手册

```jsonc
{
  "id": "howto-persona",
  "name": "改人格的方法",
  "desc": "改人格卡的标准流程：备份→改→验证",
  "match": ["persona", "人格", "性格"],   // 方法匹配用（§3.4）
  "instruction": "（方法提示词模板，{subject}/{want} 占位符）",
  "code": "",              // 可选 Python 代码模板（D7）；非空时执行走 run_python 通道
  "enabled": true,
  "source": "preset"       // preset | user | learned
}
```

**技能不进决策输入的「选项」，只进「方法库目录」与执行前的方法解析**（D12）。
做事回合里她带着全套工具，手册没写的她也可以做——安全边界不靠说明书，
靠 §4.2 的闸门与审计。

**三个来源**：

| 来源 | 存哪 | 谁维护 | 面板 |
| --- | --- | --- | --- |
| 预设（preset） | 模块内置常量，随版本走 | 我们 | 只读 |
| 用户自定义（user） | `api.dataDir('skills-user.json')` | 主人（面板增删改查） | 可编辑 |
| 学会的（learned，现有 P4.2） | `api.dataDir('skills/')` | 她自己（探索沉淀 + 复现 2 次） | 只读 |

同 id 冲突时 user > learned > preset（主人定义优先）。

### 4.2 三条「改自我」通道的安全边界

| 通道 | 权限 | 闸门 | 回滚 |
| --- | --- | --- | --- |
| **改人格卡**（D9） | L1 直改 | `personaBackup`（默认开）=改前把当前人格卡复制到 `persona-backups/<时间戳>-<id>.md`；每次改动审计留痕；每日一页必提一句 | 面板「人格历史」从备份一键回滚；`personaBackup=false` 时无备份（主人自担，面板明示） |
| **改模块配置**（D10） | ext.* 全开放 | **密钥键硬禁**：键名（含路径段）命中 `/passw|token|secret|cookie|sessdata|apikey|api_key|key$/i` 一律拒；**C5 例外**：`ext.autotelic` 的 `maxSteps / maxTasksActive / budgetActionsPerHour / actTimeoutMs / scriptTimeoutMs` 上限键她改不动；每次改动审计记 old→new | 审计里有原值，面板改动历史可一键还原 |
| **写用户模块** | 现有通道不动 | `autotelic_write_module` 原样（checkDef 校验、框架锁死、写坏仅该模块不可用） | 删目录即回退 |

> **残余风险复核点（主人知悉）**：D10 全开放下，`security.ssrfMode`、`security.dangerConfirm`、
> `platforms.*` 这类**治理/安全键**她理论上也摸得到（都不含密钥字样）。
> 现有缓解：审计 old→new + 面板改动历史 + 每日一页必提。
> 若实测发现她乱动治理键，下一版把 security.* 加进硬禁清单——**先按主人口径全开放，实测再说**。

### 4.3 出厂手册首发清单（七条，D8；角色 = 方法库基础藏书，不是任务菜单）

**改自我四条（主轴）**：

| id | 手册 | 内容要点 | match |
| --- | --- | --- | --- |
| `howto-persona` | 改人格的方法 | 备份流程（personaBackup）→ 找到人格卡对应条目 → 一次只改一处 → 自读验证 → 审计交代；改坏了怎么回滚 | persona/人格/性格/说话 |
| `howto-config` | 调配置的方法 | 先想清楚改哪个键为什么 → 密钥键硬禁自不必试 → 一次最多 3 个键 → 改完自测 → 审计 old→new | config/配置/设置/参数 |
| `howto-module` | 造模块的方法 | 能力缺口怎么发现 → autotelic_write_module 通道与格式 → checkDef 校验 → 热加载观察 → 写坏的教训怎么记 | module/模块/能力/工具 |
| `howto-skill` | 沉淀技能的方法 | 什么经验值得存（可复用、有步骤）→ 提示词模板写法 / 代码模板写法 → 复现 2 次才 learned | skill/技能/方法/学会 |

**日常三条**：

| id | 手册 | 内容要点 | match |
| --- | --- | --- | --- |
| `howto-dive` | 查资料写笔记 | 检索克制（只查相关记忆与 2~3 个文件）→ 结论写笔记 → 值得说走 propose_say | dive/查/资料/研究/笔记 |
| `howto-memory` | 整理记忆 | 流水要点补进记忆的判重与纠错口诀 | memory/记忆/整理 |
| `howto-share` | 分享的说法 | 挑值得说的一件 → propose_say 交出站治理 → 安静时段攒着 | share/说/分享/告诉 |

（手册里**没有**的事她照样能做——手册是藏书不是围栏；她探索出的新方法沉淀后，
方法库自然变厚。）
